    Developers

    Run it on your own machine

    Everything on this page is a replay of files in results/. To watch it happen for real, run the lab yourself: the same page then switches to live mode and follows your run second by second.

    1Start the lab

    Needs Docker with Compose v2, about 5 GB of free memory and 6 GB of disk.

    git clone https://github.com/shanurwan/pg-pressure-lab
cd pg-pressure-lab
scripts/lab up
scripts/lab seed     # 200k accounts, 2M positions, 20M orders

    The seed is the slow part: a few minutes. ORDERS=1000000 scripts/lab seed for a quick try.

    2Open live mode

    This site, served by the lab, reading your runs as they are written.

    scripts/lab live
# open http://localhost:58090

    Live mode streams one frame per second from /live/events (Server-Sent Events). The badge above the 3D view turns LIVE.

    3Break it, then fix it

    scripts/lab rounds batch
scripts/lab run batch naive
scripts/lab run batch naive-failfast
scripts/lab run batch chunked
go run ./cmd/report -scenario batch

    Each run writes results/<scenario>/<round>/<time>/. Rebuild this site's data with go run ./cmd/sitedata.

    The frame format (replay files and the live stream use the same one) 
    { "t": 42,
  "ops": { "order": { "n": 75, "ok": 75, "p50": 14.9, "p99": 210.0, "errors": {} } },
  "db":  { "pg_active": 3, "pg_idle_in_tx": 0, "pg_lock_wait": 0, "pg_total": 21,
           "longest_xact_s": 12.0, "bouncer_cl_waiting": 0, "bouncer_maxwait_ms": 0,

    Ask an AI assistant about the runs

    The lab ships an MCP server (cmd/mcp), so Claude or any MCP client can read the same recorded runs this page replays: compare rounds, zoom into the seconds around a failure, and ask which signal moved first. With -allow-run it can also run a drill on your local lab and read the result.

    1Add it

    cd pg-pressure-lab
claude mcp add pg-pressure-lab -- \
  go run ./cmd/mcp -repo "$PWD"

# let it run drills on your lab too:
claude mcp add pg-pressure-lab -- \
  go run ./cmd/mcp -repo "$PWD" -allow-run

    2The tools

    list_rounds what each round changes
    list_runs headline numbers and the comparison table
    get_timeline second by second, every layer
    first_signals which signal rose first, and how long before the first failure
    run_drill run one round (only with -allow-run)

    3Ask it

    "Compare naive and naive-failfast. Why did one recover and the other not?"

    "For the latest naive run, what should we have alerted on, and how much warning would it have given?"

    "Run batch chunked at 150 req/s and tell me if anything failed."
